## 二、完整故障记录（16 个问题）

### 问题 1：JS 主脚本解析失败 —— 逗号误用

**现象**：页面加载后所有按钮无反应，链状态始终显示"连接中…"

**根因**：`loadRecords` 函数中 `for...of` 循环的字符串拼接结尾用逗号：
```javascript
'</td></tr>',    // ❌ 逗号
}
```
逗号导致 `}` 被解析为表达式的一部分，整个脚本 SyntaxError。

**解决**：
```javascript
'</td></tr>';    // ✅ 分号
}
```

**反思**：
- ✅ 字符串拼接中用 `,` 和 `;` 语法含义完全不同
- ✅ 每次 JS 修改后必须 `node --check main.js` 验证
- ✅ esprima 旧版不支持 `?.` 可选链，会误报，优先用 Node 原生检查

---

### 问题 2：`loadRecords()` 变量引用错误 —— 全局污染

**现象**：`ReferenceError: did is not defined at Array.map`

**根因**：`loadRecords` 函数中出现多个未定义/错误变量：
```javascript
// 错例 1
recordsTotalPages = Array.isArray(data) ? 1 : (data.total_pages || 1);
// 'data' 未定义，应为后端返回的对象

// 错例 2
rec.data_(did || '').substring(0, 22)
// 'data_' 不是合法属性，'did' 作用域不对
```

**解决**：修正所有变量引用，`.map()` 回调内统一用 `rec.data_did`

**反思**：
- ✅ API 返回格式变更时必须 grep 所有 JS 引用
- ✅ Vanilla JS 无 TypeScript 类型检查，全靠人工审查
- ✅ `console.error(e)` 在 `catch` 块中不会阻断执行但会丢失上下文

---

### 问题 3：`resetForm()` 单引号字符串跨行 —— 经典 JS 陷阱

**现象**：页面完全无反应，无 API 请求，无 Console 日志

**根因**：
```javascript
'检疫编号: JC2024-00158\n检疫日期...'
```
单引号字符串不能跨行，JS 解析器在 `\n` 处报 SyntaxError，后面的 `init()` 全部不可用。

**解决**：改用反引号模板字符串：
```javascript
`检疫编号: JC2024-00158
检疫日期...`
```

**反思**：
- ✅ JS 中只有反引号 `` ` `` 支持多行字符串
- ✅ Python 脚本中用 `\n` 写 JS 字符串时极易出现字面 `\n` 而非换行符
- ✅ 这是本次开发中反复出现 3 次的问题

---

### 问题 4：`app.py` 被截断为 0 字节 —— SFTP 写入失败

**现象**：Flask 进程死亡，所有 API 返回 500

**根因**：SFTP `sftp.file(path, 'w')` 写入中途 SSH 连接断开，`app.py` 变成空文件

**解决**：从 `__pycache__/app.cpython-310.pyc` 反编译恢复完整代码

**反思**：
- ✅ 关键文件写入前应先备份
- ✅ 使用 `write_to_temp + mv` 原子替换更安全
- ✅ `.pyc` 文件可以在紧急情况下作为恢复来源

---

### 问题 5：`extract_metadata()` 缺参数 —— API 静默 500

**现象**：`POST /api/submit` 返回 HTML 错误页，前端 JSON 解析失败

**根因**：`extract_metadata(raw, dtype)` 需要两个参数，调用时只传了 `raw`

**解决**：传入 `dtype` 参数

**反思**：
- ✅ API 报错时检查 Flask journal (`journalctl -u`) 比看前端更直接
- ✅ `except:` 吞掉所有异常是调试的最大敌人

---

### 问题 6：模板缓存服务 0 字节旧文件 —— Jinja2 不自动刷新

**现象**：修改 `index.html` 后 curl 能拿到新内容，但浏览器看到的是旧的

**根因**：Flask 默认缓存模板（生产模式 `TEMPLATES_AUTO_RELOAD=False`）

**解决**：
```python
app.config['TEMPLATES_AUTO_RELOAD'] = True
app.jinja_env.auto_reload = True
```
加 HTTP 头：`Cache-Control: no-store, no-cache, must-revalidate`

### 问题 7：缩进错误 —— `db.execute` 在 `with` 块外

**现象**：Jinja2 模板中 `preload_records` 始终为空，"暂无存证记录"永远显示

**根因**：
```python
with get_db() as db:
    rows = db.execute('...').fetchall()
preload_records = records_to_list(rows)    # db 已关闭
total_count = db.execute('...').fetchone()  # ❌ 缩进错误，在 with 块外
```
`except:` 吞掉异常，无日志输出，花 3 小时追查"缓存问题"

**反思**：
- ✅ Python 缩进 = 功能定义，缩进错一个空格就会在执行路径外
- ✅ 用户 3 次提醒"正视自己的失误"，最终确认是缩进错误
- ✅ 生产代码必须有明确的日志输出

### 问题 8：新上链记录无时间戳 —— SQL 列数不匹配

**现象**：新提交的记录 `timestamp` 列为空

**根因**：
```python
# 12 列
INSERT INTO commitments(..., timestamp) 
# 13 个 ?
VALUES(?,?,?,?,?,?,?,?,?,?,?,?,?)  # ❌ 多写了一个 ?
```
Trigger：`sqlite3.OperationalError: 13 values for 12 columns`

**解决**：对齐为 12 个 `?` 对应 12 列

### 问题 9：PHFRFM 路径 DID 解码错误 —— LSB/MSB 序不一致

**现象**：DID `did:test123` 嵌入 PHFRFM 零水印后提取出来是乱码

**根因**：
- 编码时用 `np.unpackbits` (MSB first)
- 解码时用 `packbits` 但 `did_bit_len < len(recovered)` 用 `<` 而非 `<=`，跳过解码
- 修复后仍需统一位序

**解决**：统一使用 MSB 序，修正 `<=` 边界条件

---

### 问题 10：reveal API 用 GET 而非 POST

**现象**：`揭示失败: Unexpected token '<', '<!doctype ...' is not valid JSON`

**根因**：JS 端 `fetch('/api/reveal/' + did)` → GET 请求，但后端只注册了 `POST /api/reveal`

**解决**：改为 `securePost('/api/reveal', { data_did: did })`

### 问题 11：wm-mode-tabs 被误读为"弹窗"

**现象**：用户报告右上角 "毒圈(放大100x)" 弹窗，实际是 `wm-mode-tabs` 中的 "差异(放大100x)" 按钮

**根因**：
- `wm-mode-tabs` 定位在 `position: absolute; bottom: 8px`，依赖父容器 `.wm-compare`
- 字体小 (10px)，OCR 或视觉识别易混淆
- 用户描述为"弹窗"其实是静态 UI 控件

**解决**：
- 简化按钮文字："差异(放大100x)" → "差异"
- 添加 `title` 属性明确语义
- 确认这不是 bug，是 UI 控件被误解

### 问题 12：DID 匹配逻辑自相矛盾 —— `wmEmbedParams.did` 为空

**现象**：提取 DID 与期望完全一致，但显示"失配 (字符相似度 100%)"

**根因**：`wmEmbedParams.did` 是嵌入时传入的 DID（可能来自之前的空输入），但 `wm-text.value` 是当前输入框内容。两个不一致：
- 显示用 `wm-text.value`（正确 DID）→ 用户看到"完全一致"
- 比较用 `wmEmbedParams.did`（空字符串）→ 后端判断"失配"

**解决**：
1. 后端 `embed` 时 `did_str.strip()`
2. `custom_attack` 直接从 `original_bits` 重构期望 DID
3. 加入字节级诊断（BER / hex / 首个差异位置）
4. 前端优先用后端返回的 `ext.match` 而非 JS 自己比较

### 问题 13：分页 div 在 `overflow-x:auto` 容器内

**现象**：分页控件不显示

**根因**：
```html
<div style="overflow-x:auto">
  <table>...</table>
  <div id="records-pagination"></div>  <!-- 被 overflow 截断 -->
</div>
```

**解决**：移到容器外：
```html
<div style="overflow-x:auto">
  <table>...</table>
</div>
<div id="records-pagination"></div>
```

### 问题 14：分页 API 返回对象但 `loadRecords` 用数组接口

**现象**：存证记录表空白

**根因**：`/api/records` 带分页参数返回 `{records, total, page}` 对象，但 JS 直接 `records.map()` 失败

**解决**：`loadRecords` 同时兼容两种格式：
```javascript
const records = Array.isArray(data) ? data : (data.records || []);
recordsTotal = Array.isArray(data) ? data.length : (data.total || records.length);
```

### 问题 15：`let` 声明位置导致 `recordsPage` 未定义

**现象**：`recordsPage` 在 `loadRecords` 调用时是 `undefined`，API URL 变成 `?page=undefined`

**根因**：`let recordsPage = 1` 声明在 `loadRecords` 函数下方，JS 中 `let` 不提升

**后果**：分页 API 用默认值 (page=1) 返回，但 `recordsTotalPages` 计算错误

**解决**：将 `let` 声明移到函数之前

## 七、核心经验总结

### 开发纪律

在 Vanilla JS + Flask 这类无框架约束的项目中：

1. **每次部署后必须 `node --check main.js`**：5 次部署导致全功能不可用，全因 JS 语法错误。人可靠但会疲劳，脚本不会忘记。

2. **Python 缩进即功能定义**：`with` 块内外缩进差一级 = 逻辑完全不同。`except:` 吞异常导致 3 小时无效排查。

3. **API 格式变更时 grep 所有引用**：`/records` 从数组变成对象 → JS `.map()` 静默失败。手动维护兼容层。

4. **不要相信 `except:`**：每个异常被吞掉都意味着未来几小时的调试。至少 `except Exception as e: print(e)`。

5. **用户 Console 截图是金钥匙**：`ReferenceError: did is not defined` → 30 秒定位。之前花 1 小时查 CSS/缓存全是错的。

6. **正视失误，不找借口**：用户 3 次指正——缩进不是缓存、JS 就是 JS、别回避责任。承认错误比甩锅更快。

### 技术选择反思

| 决策 | 正确 | 代价 |
|------|------|------|
| Vanilla JS (无框架) | 部署简单，无构建工具 | 无类型检查，bug 多 |
| Flask (轻量后台) | 开发快，Python 生态好 | 模板缓存坑，生产配置敏感 |
| SQLite 本地缓存 | 查询毫秒级 | 需要手动同步链上数据 |
| 长安链 chain1 (现有集群) | 复用部署成果 | 链上查询依赖 cmc CLI |

### 给后续维护者的建议

- **部署前跑 `check_deploy.py`**：一键检查 Python 语法、JS 语法、API 端点、关键函数存在性
- **分页 API 保持向后兼容**：无参数返回数组（旧格式），有参数返回 `{records, total}`（新格式）
- **PHFRFM 零水印**：25 阶 5x tile 扩展可支持 58 字符 DID，需要约 3-5 秒计算
- **时间戳**：由 `datetime.utcnow()` 自动生成，如果缺失说明 SQL 插入有问题
- **日志位置**：`/home/ljh/trust_verification/app.log` + `sudo journalctl -u trust-verification`
